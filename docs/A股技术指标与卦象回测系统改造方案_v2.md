## 1. 口径双层模型（P0 定案 · 详细）

### 1.1 用户可见层（前台，必须直观）

用户只需要理解四件事：

1. **信号星期（可选）**：哪些星期允许出现指标信号（默认不限制；仅周一～周五可选）。  
2. **买入日（星期几）**：信号确认后，在**之后第一个**该星期的**交易日**买入。  
3. **平仓日（星期几）**：买入后，在**之后第一个**该星期的**交易日**强制平仓（不得与买入同一自然交易日平仓，由引擎 `strict` 规则保证）。  
4. **开盘/收盘**：买、卖分别用 open 或 close 成交。

**示例（研究默认常见配置）**

```text
信号：仅周五（可选）
买入：周一 · 开盘
平仓：周四 · 开盘
```

用户心智：**「周五信号 → 下周一买 → 之后周四平」**，而不是「entry_lag=1, hold=3」。

### 1.2 引擎计算层（后台，必须可复现）

引擎内部统一使用**交易日日历**（`TradeCalendar`），禁止按自然日硬算周六日：

| 用户配置 | 引擎行为（计算原语） |
|----------|----------------------|
| 未设 `buy_weekday` | `entry = nth_trading_day_after(signal_date, entry_lag)`，默认 `entry_lag=1`（经典 T+1） |
| 已设 `buy_weekday` | `entry = next_weekday_trading_day(signal_date, buy_weekday, strict=True)`（**覆盖** entry_lag 的步进方式，但仍是「交易日序列上的锚定求解」） |
| 未设 `exit_weekday` | 持有 `hold` 个周期/交易日后到期平仓 |
| 已设 `exit_weekday` | `exit = next_weekday_trading_day(buy_date, exit_weekday, strict=True)`（覆盖 hold 的「到期日」定位） |
| `buy_on` / `sell_on` | open \| close，决定成交价字段 |
| 止盈止损 | 与持有期/星期平仓**独立**：触发用日内高低；执行价/时点按既有风险规则（保持现有测试） |

**v2 明确**：

- **「按星期几」不是另一套经济含义**，而是 **T+N 在「锚定星期」约束下的日历求解**。  
- 文档与页面文案禁止再暗示「可以选周六买入」（UI 仅周一～周五）。  
- 所有 run 的 `run_meta` / 导出必须**同时落盘**：
  - **用户层**：`signal_weekdays`, `buy_weekday`, `exit_weekday`, `buy_on`, `sell_on`
  - **引擎层**：实际采用的解析路径说明；无 weekday 时的 `entry_lag`/`hold`；日历相关 hash（若可得）

### 1.3 双层如何对应（给研发的对照）

```text
┌─────────────────────────────────────────────────────────┐
│  前台（产品语言）                                         │
│  信号星期 · 买入星期 · 平仓星期 · 开盘/收盘                │
└───────────────────────────┬─────────────────────────────┘
                            │  API / BacktestRequest
                            ▼
┌─────────────────────────────────────────────────────────┐
│  后台（计算原语 · 一律交易日）                             │
│  TradeCalendar.nth_trading_day_after  →  T+N 步进        │
│  TradeCalendar.next_weekday_trading_day → 星期锚定求解    │
│  PortfolioBacktester：入场日 / 出场日 / session 成交      │
└─────────────────────────────────────────────────────────┘
```

代码锚点：

| 模块 | 路径 |
|------|------|
| 日历步进 | `wtpy/apps/astock/data/calendar.py` |
| 入场/出场 | `wtpy/apps/astock/strategy.py` → `PortfolioBacktester` |
| 编排与 meta | `wtpy/apps/astock/service/backtest.py` |
| 前端步骤与摘要 | `wtpy/apps/astock/web/static/index.html` |
| 测试 | `test_weekday_schedule.py`, `test_entry_lag.py`, `test_buy_sell_session.py`, `test_signal_weekdays.py` |

### 1.4 文案与验收口径（冻结）

| 场景 | 对外文案 | 禁止 |
|------|----------|------|
| 新建回测步骤 3/4 | 「信号星期」「买入日/平仓日（星期几）」 | 主路径再暴露 entry_lag/hold 高级框 |
| 历史/详情标题 | 策略 + 卦象摘要 + 日线 + 周一买·周四平等 | 只显示 `bt_xxx` 当主标题 |
| 引擎 notes / Excel 说明 | 「按交易日日历解析星期锚定；属 T+N 体系下的约束求解」 | 「自然周固定间隔」「可周六买入」 |
| v1 的 T+1 开 / T+2 收 | 作为**可选预设模板**（内部 entry_lag/hold + session），不取代星期默认 UI | 强制所有用户只能 T+2 |

### 1.5 可选预设：「经典 T+N」如何并存

不删除 T+N 能力。后续可提供一键预设（非 P0 必做）：

| 预设名 | 用户看到的说明 | 写入请求 |
|--------|----------------|----------|
| 研究·星期模板（默认） | 周一买 / 周四平等 | `buy_weekday` / `exit_weekday` 有值 |
| 经典 T+1 开买 · T+2 收卖 | 信号后第 1 个交易日开盘买，再持有至第 2 个交易日收盘卖（以产品最终定义为准） | 清空 weekday，设 `entry_lag`/`hold`/`buy_on`/`sell_on` |

两种预设**共享同一引擎**，仅请求字段不同。

在不推翻当前单次回测可用性的前提下：

```text
配置条件（指标 / 星期日程 / 卦象）
→ 单次或批量回测
→ 完整落盘与复现
→ 对比与分析
→ （后期）实验矩阵与样本外验证
→ 输出可解释的候选方案
```
