# 命理知识量化接入需求与数据模型设计

**文档版本：** V1.0  
**编制日期：** 2026年8月22日  
**适用项目：** `wtpy-master / wtpy.apps.astock`  
**文档状态：** 待产品确认  
**目标阶段：** 研究型 MVP → 样本外验证 → 模拟盘观察  

---

## 1. 文档目的

本文档用于定义将八字命理、易经卦爻及相关著作接入 AStock 系统时的：

1. 产品目标与使用边界；
2. 知识资料、版本、版权与来源治理要求；
3. 命理知识从原文到量化规则的转换流程；
4. 易经卦象与八字特征的计算模型；
5. 规则 DSL、评分模型和解释模型；
6. 数据库、文件存储、缓存和研究指纹设计；
7. 回测、实验、评价、模拟盘和正式启用门禁；
8. 分阶段实施任务、验收标准与回滚策略。

本文档不是对命理预测有效性的预设证明。系统必须把每条命理判断视为一个待验证的研究假设，通过可复现回测、样本外验证和前向观察决定其是否具有统计与经济意义。

---

## 2. 总体结论

推荐采用：

> **结构化知识库 + 确定性特征引擎 + 可审核规则 DSL + 配对回测 + RAG 引用解释**

不采用以下路径作为正式选股依据：

- 将整本书直接交给大模型，由大模型自由判断股票吉凶；
- 根据历史收益反向挑选原文解释，再包装成命理规则；
- 修改既有卦象算法而不保留旧版本；
- 把不同书籍、流派或注本的观点直接合并成一个不可追溯的总分；
- 未通过样本外验证就让命理规则影响模拟盘或实盘。

命理知识接入后应形成以下研究链路：

```text
合法书籍资料
    ↓
原文分段与来源索引
    ↓
概念、判断和条件抽取
    ↓
人工审核与规则版本冻结
    ↓
易经 / 八字确定性特征计算
    ↓
规则命中、过滤或评分
    ↓
技术指标基线配对回测
    ↓
样本外、市场阶段和稳定性评价
    ↓
模拟盘前向观察
```

## 3. 当前系统基础与差距

### 3.1 可直接复用的现有能力

| 能力 | 当前代码落点 | 可复用方式 |
|---|---|---|
| 64卦384爻计算 | `bagua/calculator.py` | 保持现有 OHLC 起卦口径，作为易经特征输入 |

| 卦象查询与导出 | `service/bagua_query.py` | 增加多书来源解释和命理评分字段 |
| 日柱数据 | `service/bagua_query.py` | 作为上市日期干支基础，升级为出生档案 |
| 爻辞规则清单 | `service/yao_rules.py` | 升级为通用命理规则清单与审核流程 |
| 预测知识库版本 | `forecast/service.py` | 复用知识版本保存、激活和回滚思路 |
| 参数空间 | `research/parameter_space.py` | 增加命理规则集、评分阈值和出生口径轴 |
| 过滤缓存 | `research/filter_cache.py` | 增加命理规则版本和特征版本缓存键 |
| 研究指纹 | `research/fingerprint.py` | 增加书籍、规则集、历法和出生档案哈希 |
| 评价中心 | `research/evaluation.py` | 增加命理增益、规则贡献和来源稳定性评价 |
| 样本外验证 | `research/validation.py` | 复用固定样本外和 Walk-Forward 验证 |
| 综合评分 | `research/scoring.py` | 保持收益、回撤、稳定性和样本外优先 |

### 3.2 当前主要差距

1. 当前日柱属于静态字段，不是完整的年月日时、十神、五行和旺衰计算引擎。
2. 当前爻辞规则来源多为简写材料名，缺少书名、版本、章节、页码和原文哈希。
3. 当前 `GuaFilter` 主要表达卦象过滤，不适合承载完整八字与跨体系规则。
4. 现有 384 条知识结构主要围绕单一卦爻状态，不能自然表达：
   - 多来源解释；
   - 流派冲突；
   - 适用周期；
   - 前置条件；
   - 强弱程度；
   - 禁用条件；
   - 八字与流年、流月、流日交互。
5. 当前研究指纹尚未记录命理书籍版本、历法引擎版本、出生口径版本和规则证据版本。
6. 当前系统没有区分“知识检索解释”和“正式量化规则”。
7. 缺少命理规则从草稿到研究、样本外、模拟盘和正式启用的晋级机制。

## 4. 项目目标与非目标

### 4.1 项目目标

#### G-01 可追溯

任意一条命理评分必须能够追溯到：

- 哪一本书；
- 哪一个版本；
- 哪一章、哪一页或哪一段；
- 原文文件哈希；
- 谁做了市场解释；
- 谁审核了量化规则；
- 当前启用的规则版本。

#### G-02 可计算

同一份输入数据、历法版本、出生口径和规则版本必须产生完全相同的特征、命中结果和评分。

#### G-03 可回测

每条规则必须能被转换为明确的：

- 输入特征；
- 条件表达式；
- 看多、看空或中性影响；
- 过滤或评分行为；
- 适用周期；
- 退出或失效条件。

#### G-04 可证伪

系统必须允许一条规则在样本外表现不佳时被降级、禁用或淘汰，不允许以解释变化替代失败结论。

#### G-05 可解释

选股结果应同时展示：

- 技术指标依据；
- 卦象或八字特征；
- 命中的规则；
- 规则贡献分；
- 来源书籍和位置；
- 风险与样本不足提示。

### 4.2 非目标

第一阶段不包含：

- 用大模型直接控制买卖；
- 自动把所有古籍内容转为正式规则；
- 立即上线自动交易；
- 将命理规则作为唯一选股来源；
- 在未确定时间口径前强行使用时柱；
- 一次性实现所有流派和所有高级格局；
- 用知识向量相似度直接代替回测信号；
- 对外提供受版权限制的书籍全文下载。

## 5. 资料范围与接入顺序

### 5.1 暂定资料清单

| 资料 | 领域 | 第一阶段用途 | 状态 |
|---|---|---|---|
| 《周易》卦辞、爻辞 | 易经 | 384爻基础原文与标准引用 | 必选 |
| 《高岛易断》或用户所称《高岛易传》 | 易经案例 | 卦爻案例、应期、倾向和风险解释 | 待确认版本 |
| 邵伟华易占相关著作 | 易经 | 现代预测方法和实操解释 | 待确认书名与版本 |
| 《三命通会》 | 八字 | 格局、五行、十神等知识来源 | 第二批 |
| 《渊海子平》 | 八字 | 子平法规则和概念来源 | 第二批 |
| 《滴天髓》及指定注本 | 八字 | 旺衰、气势、体用等知识来源 | 第二批 |
| 邵伟华《四柱预测学》或其他八字著作 | 八字 | 现代四柱规则与案例 | 待确认 |

### 5.2 推荐接入顺序

```text
第一批：周易卦爻辞 + 高岛易断 + 一本确认后的易占著作
第二批：三命通会 + 渊海子平 + 滴天髓 + 四柱预测学
第三批：跨书共识、流派对照和易经×八字组合规则
```

原因：

1. 当前系统已经有 384 爻稳定标识，易经资料接入成本较低。
2. 八字体系需要先解决股票出生时间、节气、历法和时柱假设。
3. 分批接入可以分别验证易经和八字是否产生独立增益。
4. 避免全部资料同时接入后无法判断收益来自哪一条规则。

## 6. 核心领域定义

### 6.1 四层知识模型

系统必须区分以下四层：

| 层级 | 含义 | 是否可直接交易 |
|---|---|---|
| 原文层 | 书籍原文、校注、案例 | 否 |
| 解释层 | 对原文概念和含义的人工说明 | 否 |
| 市场映射层 | 将传统概念映射为市场假设 | 否 |
| 量化规则层 | 确定输入、条件、方向、权重和周期 | 通过门禁后才可以 |

例如，“某爻利有攸往”不能直接等于“股票未来上涨”。必须增加市场映射：

```text
原文判断
→ 解释为行动倾向
→ 约定在股票研究中的含义
→ 指定适用价格周期与持有期
→ 转换为可运行条件
→ 通过配对回测验证
```

### 6.2 股票出生档案

八字规则需要定义股票的“出生时间”。系统必须允许多种口径并进行版本化实验。

| 口径 | 数据可得性 | 优点 | 风险 |
|---|---|---|---|
| 上市日期 | 高 | 稳定、全市场易获取 | 缺少自然的准确时柱 |
| 首次交易时间 | 中 | 与市场交易行为直接相关 | 历史精确时间可能缺失 |
| 公司成立日期 | 中低 | 接近企业法人诞生 | 与证券交易标的关系较远 |
| IPO批准日期 | 中 | 事件明确 | 不等于公开交易开始 |

**MVP 推荐口径：**

```text
birth_basis = listing_date
timezone = Asia/Shanghai
calendar = solar_terms
pillar_mode = three_pillars
hour_policy = unavailable
```

第一阶段只使用年柱、月柱、日柱。时柱只计算、不参与正式规则，直到：

1. 确认全市场精确首次交易时间覆盖率；
2. 对 `09:30` 假设和真实时间进行对照；
3. 证明时柱规则在样本外具有增益。

### 6.3 时序命理特征

系统需要区分：

- 股票静态命盘：出生年月日或年月日时；
- 交易日时序：流年、流月、流日；
- 市场环境：指数趋势、波动率和市场阶段；
- 股票行情卦象：现有 OHLC 卦象与爻位；
- 静态命盘和交易日之间的作用关系。

### 6.4 流派和冲突

同一概念在不同书籍、注本或流派中可能存在冲突。系统不得覆盖旧解释，应保存：

- `tradition`：易经、子平、现代四柱等；
- `school`：具体流派；
- `author_or_commentator`；
- `interpretation_id`；
- `conflict_group_id`；
- `priority_policy`：并列实验、人工优先或仅解释。

默认策略为：**冲突观点分别形成规则，不自动平均权重。**

## 8. 数据模型总览

### 8.1 关系模型

```text
metaphysics_source
    1 ── N metaphysics_edition
             1 ── N metaphysics_document
                      1 ── N metaphysics_passage
                               N ── N metaphysics_concept
                               N ── N metaphysics_rule_evidence
                                          N ── 1 metaphysics_rule

metaphysics_rule_set
    1 ── N metaphysics_rule_set_item
             N ── 1 metaphysics_rule

stock_birth_profile
    1 ── N metaphysics_feature_snapshot
             1 ── N metaphysics_rule_hit

backtest_run
    1 ── 1 run_metaphysics_binding
             N ── 1 metaphysics_rule_set
```

### 8.2 存储选型

第一阶段建议：

- 结构化元数据：沿用现有 SQLite；
- 原始文件和大文本：文件存储；
- 段落检索：SQLite FTS5 或轻量向量索引；
- 特征缓存：按日期和版本分区的 JSONL、Parquet 或现有缓存模式；
- 批量实验成熟后，再评估 PostgreSQL。

不建议第一阶段就引入独立图数据库。知识关系可先通过关系表和 JSON 字段表达，避免增加不必要运维成本。

## 9. 核心表设计

### 9.1 `metaphysics_source`

表示逻辑书目，不对应某一个具体电子文件。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `source_id` | TEXT | PK | 稳定ID，如 `zhouyi` |
| `title` | TEXT | NOT NULL | 标准书名 |
| `alternate_titles_json` | TEXT |  | 别名，例如高岛易传/高岛易断 |
| `domain` | TEXT | NOT NULL | `iching` / `bazi` / `mixed` |
| `author` | TEXT |  | 作者或传统署名 |
| `era` | TEXT |  | 年代 |
| `language` | TEXT | NOT NULL | `zh-Hans` / `zh-Hant` / `ja` |
| `copyright_status` | TEXT | NOT NULL | `public_domain` / `licensed` / `restricted` / `unknown` |
| `redistribution_allowed` | INTEGER | NOT NULL | 是否允许对外展示全文 |
| `notes` | TEXT |  | 书目说明 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

### 9.2 `metaphysics_edition`

表示具体版本、出版社、校注本或译本。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `edition_id` | TEXT | PK | 版本ID |
| `source_id` | TEXT | FK | 逻辑书目 |
| `publisher` | TEXT |  | 出版社 |
| `publication_year` | INTEGER |  | 出版年份 |
| `isbn` | TEXT |  | ISBN |
| `editor_or_translator` | TEXT |  | 校注、整理或译者 |
| `edition_label` | TEXT | NOT NULL | 用户可识别版本名 |
| `page_system` | TEXT |  | 印刷页、PDF页或章节定位 |
| `license_note` | TEXT |  | 授权与使用限制 |
| `status` | TEXT | NOT NULL | `draft` / `verified` / `disabled` |

唯一约束建议：

```text
UNIQUE(source_id, edition_label, publication_year, isbn)
```

表示实际导入的文件。

| 字段 | 类型 | 约束 | 说明 |

| `edition_id` | TEXT | FK | 所属版本 |
| `file_name` | TEXT | NOT NULL | 原文件名 |
| `file_path` | TEXT | NOT NULL | 本地路径 |
| `file_type` | TEXT | NOT NULL | PDF/DOCX/TXT/XLSX |

| `extraction_method` | TEXT |  | 原生文本/OCR/人工录入 |

| `page_count` | INTEGER |  | 页数 |
| `extraction_status` | TEXT | NOT NULL | `pending` / `ready` / `failed` |

### 9.4 `metaphysics_passage`

知识检索和引用的最小原文单元。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `passage_id` | TEXT | PK | 段落ID |
| `document_id` | TEXT | FK | 来源文件 |
| `chapter_path` | TEXT |  | 卷/章/节层级 |
| `page_start` | INTEGER |  | 起始页 |
| `page_end` | INTEGER |  | 结束页 |

## 10. 规则 DSL 设计

### 10.1 设计原则

规则 DSL 必须：

- 只允许白名单操作符；
- 不执行任意 Python；
- 能序列化、哈希和版本化；
- 能输出条件命中过程；
- 缺失特征时默认 `fail_closed`；
- 支持单规则测试；
- 支持同一规则不同权重形成独立版本；
- 支持过滤、评分和退出三类效果。

### 10.2 条件操作符

第一阶段建议支持：

```text
all
any
not
eq
neq
in
not_in
gt
gte
lt
lte
between
contains
exists
is_missing
```

第二阶段再增加：

```text
element_generates
element_controls
stem_combines
branch_clashes
branch_harms
branch_punishes
ten_god_is
season_strength
score_sum
```

### 10.3 效果模型

```json
{
  "mode": "score",
  "direction": "bullish",
  "score_delta": 1.5,
  "horizon_days": [5, 20],
  "min_confidence": 0.7,
  "position_cap_delta": 0.0,
  "exit_signal": false
}
```

`mode` 支持：

- `explain_only`：只解释；
- `filter_include`：命中才保留；
- `filter_exclude`：命中则排除；
- `score`：增加或减少分数；
- `exit`：退出候选，但第一阶段不建议启用。

### 10.4 易经规则示例

以下仅用于展示结构，不代表已确认规则：

```json

  "rule_id": "iching_example_001",

  "domain": "iching",
  "condition_ast": {
    "all": [
      {"field": "iching.state_id", "op": "in", "value": ["24-1", "46-1", "11-1"]},
      {"field": "market.regime", "op": "neq", "value": "bear"}

  },
  "effect": {
    "mode": "score",
    "direction": "bullish",
    "score_delta": 1.0,
    "horizon_days": [5, 20]
  }
}
```

## 11. 易经知识接入设计

### 11.1 计算与解释分离

现有 OHLC 起卦算法属于“计算层”，新增书籍属于“知识解释层”。第一阶段不得因为新书内容修改现有：

- 价格格式化；
- 数字求和；
- 上下卦映射；
- 动爻计算；
- `state_id`；
- 主卦与变卦计算。

如未来需要测试新的起卦方法，必须新增：

```text
iching_calc_version
iching_method
```

并与旧算法并行回测，不得覆盖历史结果。

### 11.2 多来源卦爻知识

现有单条 384 知识应升级为：

```text
一个 state_id
    ├── 周易原文
    ├── 高岛易断解释
    ├── 邵伟华相关解释
    ├── 用户人工总结
    ├── 支持证据
    ├── 反对或限制证据
    └── 多个独立量化规则
```

### 11.3 规则粒度

易经规则至少支持以下粒度：

- 主卦；
- 主卦 + 动爻；
- 变卦；
- 主卦 + 动爻 + 变卦；
- 行动信号；
- 周卦；
- 月卦；
- 周卦与月卦共识；
- 卦象转强或转弱；
- 与市场阶段组合。

## 12. 八字特征引擎设计

### 12.1 历法要求

历法引擎必须明确：

- 使用公历输入；
- 时区为 `Asia/Shanghai`；
- 月柱按节气切换，不按农历初一切换；
- 年柱切换口径必须版本化；
- 闰年和跨日计算必须有固定测试；
- 1900年前锚点算法如被使用，必须有权威历表对拍；
- 不允许仅靠字符串表格拼接生成正式命盘。

### 12.2 MVP 特征

第一阶段计算：

- 年柱、月柱、日柱；
- 天干、地支；
- 五行；
- 阴阳；
- 日主；
- 基础十神；
- 地支藏干；
- 五行数量和比例；
- 月令；
- 静态合、冲、刑、害；
- 流年、流月、流日；
- 静态命盘与交易日的基础关系。

第一阶段暂不正式启用：

- 时柱依赖规则；
- 大运起运；
- 复杂格局自动判定；
- 从强、从弱等争议较大规则；
- 神煞大规模组合；
- 自动用神结论；
- 自由文本生成的旺衰分数。

### 12.3 特征命名规范

示例：

```text
bazi.birth.year.stem
bazi.birth.year.branch
bazi.birth.month.stem
bazi.birth.month.branch
bazi.birth.day.stem
bazi.birth.day.branch

bazi.relation.day_vs_flow_day

temporal.flow_month.branch
temporal.flow_day.element
```

所有特征必须附：

- 类型；
- 允许值；
- 计算函数；
- 缺失策略；
- 算法版本；
- 单元测试样例。

## 13. 命理评分模型

### 13.1 第一阶段评分

采用简单、透明的加权求和：

```text
metaphysics_score
= iching_score
+ bazi_score
+ consensus_bonus
- conflict_penalty
- data_quality_penalty
```

不使用神经网络或大模型隐式评分。

### 13.2 分数范围

建议标准化为：

```text
[-5.0, +5.0]
```

并输出：

- `raw_score`；
- `normalized_score`；
- `rule_hit_count`；
- `bullish_hit_count`；
- `bearish_hit_count`；
- `conflict_count`；
- `quality_penalty`；
- `confidence_level`。

### 13.3 与技术指标结合

第一阶段建议三种模式：

| 模式 | 行为 | 用途 |
|---|---|---|
| `explain_only` | 不改变候选 | 验证数据与解释 |
| `filter` | 达到阈值才保留 | 与现有卦象过滤一致 |
| `rank_boost` | 对技术候选重新排序 | 推荐主研究模式 |

不建议第一阶段使用命理规则单独从全市场生成买入信号。

## 15. 研究评价与统计门禁

### 15.1 必须评价的指标

- 总收益；
- 年化收益；
- 最大回撤；
- Sharpe；
- Sortino；
- Calmar；
- 胜率；
- 盈亏比；
- Profit Factor；
- 成交次数；
- 信号保留率；
- 相对基线增益；
- 年度盈利比例；
- 市场阶段表现；
- 样本外衰减；
- 参数邻域稳定性；
- 单规则贡献；
- 规则冲突次数；
- 股票横截面覆盖率。

### 15.2 过拟合控制

命理规则组合数量可能非常大，必须：

1. 在测试前冻结规则和方向；
2. 保留未参与规则设计的样本外区间；
3. 使用 Walk-Forward；
4. 按规则家族进行多重检验控制；
5. 保留全部失败实验，不只保留优胜结果；
6. 禁止根据测试结果反复修改同一规则后继续声称是同一假设；
7. 将规则修订视为新版本重新验证；
8. 对极少样本规则标记 `insufficient_sample`。

### 15.3 建议门禁

以下为初始建议值，后续可配置：

| 门禁 | 建议要求 |
|---|---|
| 数据完整 | 核心输入无缺失，出生口径和历法版本明确 |
| 最低样本 | 全样本成交不少于100，单个样本外窗口不少于30 |
| 样本外 | 至少3个 Walk-Forward 测试窗口 |
| 收益来源 | 不允许单一年份贡献绝大多数收益 |
| 市场阶段 | 至少两个市场阶段不劣于基线 |
| 交易成本 | 扣除费率、滑点后仍有增益 |
| 参数稳定 | 相邻阈值和持有期不出现断崖式失效 |
| 最大回撤 | 不显著恶化，或恶化有明确收益补偿 |
| 前向观察 | 模拟盘达到约定观察周期后再评估生产启用 |

### 15.4 规则晋级

```text
draft
  ↓ 原文和解释审核
expert_reviewed
  ↓ 可执行规则检查
research_only
  ↓ 固定样本外通过
oos_passed
  ↓ 前向模拟观察
paper_trading
  ↓ 风控和审批
production
```

任何阶段均可进入：

```text
rejected / retired
```

## 16. RAG 与大模型使用边界

### 16.1 允许用途

- 从书籍中检索相关原文；
- 根据指定字段辅助生成规则草稿；
- 提取概念、别名和候选关系；
- 生成个股命中规则的自然语言解释；
- 汇总不同书籍的支持和冲突观点；
- 帮助审核人员定位原文。

### 16.2 禁止直接进入正式信号的用途

- 大模型自由输出股票评分；
- 大模型自由选择买入或卖出；
- 无原文引用的规则自动启用；
- 将向量相似度当成看多或看空分数；
- 根据回测结果自动重写原文含义；
- 使用未固定模型、温度和提示词生成可复现规则结果。

### 16.3 结构化抽取流程

```text
段落
→ 大模型生成候选概念与候选规则
→ JSON Schema 校验
→ 原文位置自动绑定
→ 人工逐条审核
→ DSL 编译测试
→ 进入 draft 规则库
```

大模型输出默认只能进入 `draft`。

## 19. 安全、版权与审计

### 19.1 文件安全

- 原书文件默认只读；
- 文件路径不直接通过 API 暴露；
- 上传文件校验扩展名、MIME、大小和哈希；
- 不执行文档内宏；
- OCR和解析进程使用受限工作目录；
- 禁止用户输入拼接系统命令。

### 19.2 版权

- 古籍原文、现代整理本、注本、译本和邵伟华著作分别登记版权状态；
- `restricted` 资料默认只允许内部检索；
- 对外展示时优先显示短引用、页码和解释；
- 不提供完整受限书籍导出；
- 商业部署前完成专项授权核查；
- 文档和系统声明不构成法律意见。

### 19.3 审计

以下操作必须写审计日志：

- 导入、替换或删除资料；
- 修改段落校对结果；
- 创建或修改规则；
- 审核规则；
- 激活或回滚规则集；
- 将规则晋级到模拟盘或生产；
- 修改股票出生口径；
- 修改历法或评分版本。

## 22. 分阶段实施计划

### P0 需求和资料冻结

**目标：** 确认书籍、版本、版权和第一批规则范围。

- 确认文件格式；
- 确认股票出生口径；
- 冻结 MVP 只做易经还是易经+三柱。

验收：

- 每本书有唯一 `source_id` 和 `edition_id`；
- 版权状态不为未处理；
- 第一批资料和非目标明确。

### P1 语料库和来源治理

**目标：** 完成资料导入、OCR、段落、检索和版本哈希。

主要文件：

```text

metaphysics/provenance.py
service/metaphysics_import.py
```

验收：

- 可导入至少三种格式；
- 每段可回到书名、版本和页码；
- 文件变更产生新哈希；
- 受限原文不会被公开导出。

### P2 易经多来源知识 MVP

- 支持解释、过滤和评分；

验收：

- 现有卦象查询结果不回归；
- 每条规则至少有一个原文证据；
- 同一 `state_id` 可显示多个来源；
- 命理关闭时回测结果不变。

### P3 三柱特征引擎

**目标：** 上市日期三柱和交易日时序特征。

主要文件：

验收：

- 缺失数据有明确降级；
- 三柱特征可缓存、可复现。

### P4 通用规则 DSL 和评分

验收：

- 规则集可冻结、激活和回滚；
- 规则版本变化正确失效缓存。

### P5 回测和实验中心接入

**目标：** 支持基线、易经、八字和组合配对实验。

主要改动：

service/backtest.py

### P6 样本外与模拟盘门禁

**目标：** 建立规则晋级和前向观察闭环。

验收：

## 23. 推荐首期 MVP

### 23.1 范围

第一期建议只做：

- 《周易》卦爻辞；
- 用户确认版本的《高岛易断》；
- 一本确认后的邵伟华易占著作；
- 现有 OHLC 384 爻算法；
- 20至30条人工审核规则；
- `explain_only`、`filter`、`rank_boost` 三种模式；
- `3/5/10/20/60` 交易日持有周期；
- 基线和易经增强配对回测。

### 23.2 暂缓

- 完整四柱；
- 时柱正式规则；
- 大运；
- 大规模神煞；
- 自动用神；
- 跨体系规则；
- 命理独立选股；
- 自动交易。

### 23.3 MVP 成功标准

1. 资料和规则均可追溯；
2. 同一输入结果可复现；
3. 命理关闭时现有系统零行为变化；
4. 可自动生成基线与增强组；
5. 至少完成一个完整样本外实验；
6. 页面能够解释命中的原文来源和规则；
7. 即使结果无增益，也能得到明确、可信的否定结论。

## 24. 风险与待确认决策

### 24.1 P0 必须确认

| 编号 | 决策 | 推荐默认值 |
|---|---|---|
| D-01 | 高岛书籍准确书名与版本 | 以用户实际文件为准 |
| D-02 | 邵伟华具体书名与版本 | 先确认封面、目录、ISBN |
| D-03 | 第一批是否接入八字 | 否，先完成易经 MVP |
| D-04 | 股票出生口径 | 上市日期 |
| D-05 | 时柱策略 | 第一阶段禁用 |
| D-06 | 命理对选股的作用 | 先解释和排序，后过滤 |
| D-07 | 原文存储位置 | 外部 `storage_root` |
| D-08 | 正式数据库 | 第一阶段 SQLite |
| D-09 | 大模型用途 | 只做抽取辅助和解释 |
| D-10 | 生产启用 | 样本外+模拟盘后人工审批 |

### 24.2 主要风险

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 传统理论到股票市场映射主观 | 规则方向不稳定 | 市场映射单独记录并可证伪 |
| 书籍和流派冲突 | 分数含义混乱 | 分流派、分规则独立实验 |
| 出生时间不唯一 | 八字特征不稳定 | 出生口径版本化和对照实验 |
| 大量组合过拟合 | 历史结果虚高 | 冻结规则、样本外、Walk-Forward |
| OCR错误 | 原文和规则证据错误 | 段落审核和质量分 |
| 版权不明确 | 无法商业部署 | 版本级授权状态和展示限制 |
| LLM幻觉 | 伪造来源或解释 | 所有规则必须绑定真实段落 |
| 数据偏差 | 回测结论虚假 | 点时股票池、退市覆盖、成本和公司行为 |
| 规则版本漂移 | 历史结果不可复现 | 不可变规则集和完整研究指纹 |
