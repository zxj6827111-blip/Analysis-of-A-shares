## 阶段与文件

### 阶段 0：误判终态自愈（事故修正）

- 现场：9/11 周的 TaskState 被写成 `no_trading_week`（终态），但该周下一个
  自然周（9/14~9/18）明明有交易日——写盘时的日历视图是"越过该周却整周无
  交易日"（稀疏日历/数据面中间态），属误判。`should_complete_further` 对
  `no_trading_week` 恒 False（契约：日历推导的合法终态），该周被永久锁死。
- 修复：`screen_tracking.should_recompute` 在判定前拦截——state 记
  `no_trading_week` 而当前日历下该周**有**交易日 → `no_trading_week_recovered`
  重算（`screen_contract` 纯函数不动，自愈留在知道日历的那一层）。
- 清理：删除本机误判的 `state_track_20260911_*.json`。

### 阶段 1：产物增强（schema v2）

- `TRACKING_SCHEMA_VERSION` `1`→`2`（algo_version 不动：收益算法没变）。
- 行内新增：`name`（结算时用 `stock_names.resolve_stock_name` 解析，按票缓存；
  缺名留空串，绝不拿代码冒充）、`close_week_end`（窗末/周五收盘价，前端不再
  从 `daily` 反推）。
- 代码形态：`normalize_stock_code` 统一取 6 位码（产物 code 可能是
  `SSE.STK.600033` 或 `SZSE.000003.SZ`，不能靠 `split(".")`）。
- L2 接口：透出 `track_week` / `track_week_dates` / `short_week` /
  `window_ended`；`pending_picks` 读取时补名称。
- 导出：周明细 sheet 加「名称」「周五收盘」「见顶星期」三列（与 UI 同源字段）。

### 阶段 2：一级栏目化

- 导航 `data-view="track"`（回测与卦象之间）；`section.view#view-track`；
  `wb-track-panel` 从工作台迁出；工作台页签 4→3。
- CSS 作用域由 `#wbRoot` 改为类选择器 `.wb-root`（两个视图共用一套规则）。
- `switchModule("track")` 接管原 `wbSetMode("track")` 的初始化；`?module=track`
  加入白名单（`getCurrentModule` 与 boot 两处）。
- **关键坑**：原按钮绑定挂在 `wbBind()`（`wbInited` 守卫，只有进过卦象才
  执行）→ 首屏直达 `?module=track` 时搜索/导出/返回全部失效。抽出独立的
  幂等 `wbtBind()`（DOM 标志位守护，避免与脚本初始化顺序耦合），在
  `switchModule("track")` 与 `wbBind()` 两处调用。
- 跨视图跳转：`wbtQueryFromTrack` 先 `switchModule("bagua-query")` 再
  `wbSetMode("query")`。

### 阶段 3：L2 列表页

- 默认列：代码 / 名称 / 周一开盘价 / 周五收盘价 / 最高涨幅（含见顶星期）/
  本周涨幅（随口径）/ 可成交性 / 状态 / 操作。
- 「详情」展开行：逐日收益按 `track_week_dates` **实际交易日**渲染（短周、
  停牌日如实显示），加最低相对入场、峰谷回撤、双口径、基准与超额。
- 表头点击排序（缺值恒沉底，不把无数据票排最前）；默认本周涨幅降序。
- 一字涨停买不进 → 显著标签；窗口未结束 → 「进行中（未结算）」横幅 +
  状态列「进行中」（不再显示成"已结算"）。
- 待结算 chips 带名称 + 告知如何结算（每周五晚自动 / 补算入口）。

### 阶段 4：补算指定历史周

- 新路由 `api_routes/track_backfill.py`：
  - `POST /api/v1/bagua/track/backfill` `{week:"YYYYMMDD"}` 或 `{weeks_back:1..52}`
  - `GET  /api/v1/bagua/track/backfill/status`
- 实现：请求线程只校验 + 投递；单 worker 线程起 CLI 子进程
  （`track-weekly --week D --backfill 1` / `--backfill N`），全局参数
  （`--storage`/`--indicator-dir`）放在子命令**前**。
- 互斥复用既有机制：子进程自己抢 heavy-job 锁，抢不到记待办、退出码 3，
  由 serve 的 `_auto_heavy_job_retry` 退避重试；同周在途返回 409。
- 任务中心聚合第 4 个数据源（kind=`track_backfill`），点开跳跟踪栏目。
- 语义提醒常驻：补算=按**当前规则**重建，不等于当时实际发布的名单。

## 第二轮用户反馈（同日深夜）

| # | 反馈 | 对策 |
|---|------|------|
| 1 | 口径固定「首日开盘」，「信号收盘」隐藏掉 | 移除口径切换按钮与 `wbtSetCaliber`；`wbt.caliber` 固定 `exec`；L0/L1/L2 列头只标首日开盘。**产物里的 sig 口径数据保留**（只是不展示），将来恢复只需加回按钮 |
| 2 | 指标要与规则中心一致；有重复的；规则删了跟踪也要同步删 | L0/L1 接「当前规则目录」（`list_screen_rules` = 规则中心可见 ∪ 周五链预置复核规则）：删除同步过滤 + **同指纹归并**（tn6_ 与其配对源 txt_ 同公式）。实测 L0 从 16 条降到 9 条，`txt_735金叉及趋势` 归并进 `tn6_735金叉及趋势`（`merged_rule_ids` 可追溯），名称由后端直出。导出同步同口径 |
| 3 | L1 信号周列表同色，看不出涨跌 | 收益类数字加涨跌配色（`.wb-pos` 红 / `.wb-neg` 绿，A 股习惯），覆盖 L0 收益与超额、L1 收益/超额/摘要条、L2 本周涨幅 |
| 4 | 代码去掉 `SZSE.STK.` 前缀 | L2/待结算返回 `code_disp`（6 位码，`normalize_stock_code`），列表显示短码；「查卦象」仍传完整 std_code |

**顺带修掉两个既有缺陷**：

- **L1 列头与取值口径不一致**：列头随口径切换、取值却固定用信号收盘字段（`mean_ret_close_sig`/`win_rate_sig`），列头写「首日开盘」而数字是信号口径。修正为统一 exec。
- **归并后的取数缺口**：L0 归并出 canonical id 后，L1/L2 若只按单一 id 匹配，被归并掉的周（或"新导入的 tn6_ 从未进过快照、历史只有 txt_"的场景）会查不到。修法：L1 接受 `fingerprint` 参数（前端从 L0 行带上，最可靠）+ 按入口 id 反查兜底；L2 按同指纹组过滤。
- **发现并修复一处误提交**：验证信号日校验时用 `20260626` 做了真实 POST，任务被真的受理。已立刻终止（无产物落盘、锁已释放）、重启 serve 清空任务记录，并新增信号日语义校验（周中日期直接 400 并提示该填哪天）。
