## 一、逐项整改与验证

### R3-01 / P2：筛选条件改变后旧结果仍被当作当前结果，甚至可继续导出 —— 已修

**根因**（与复核一致）：筛选侧只有「条件变更就隐藏结果区」，没有条件版本概念；
`wbImportPickedFromQuery` 更是只重绘范围与摘要，既不清快照也不标记过期；在途响应
回来时也没有版本比对，所以能把已失效的结果重新显示成"本次结果"。

**整改**（`index_v3.html`）：
1. **条件版本化**：`wbs.condVersion`，任何条件变更 +1；`wbScreenChanged()` 统一承担
   「版本 +1 + 快照清空 + 结果区标记过期」，所有变更入口（规则勾选、范围选择、
   手动输入/移除、日期、组合方式、**从查询结果导入**）都走它——导入函数改为调用
   `wbScreenChanged()`（原来只调 `wbRenderSummaries()`）。
2. **提交快照**：提交时固定 `{ version, summary }` 存 `wbs.submitted`，摘要文案由
   `wbScreenSummaryText()` 单点生成（摘要区与快照共用，不会两处不一致）。
3. **过期呈现**：新增 `wbScreenResultIsStale()`（提交版本 ≠ 当前版本）与
   `wbRenderScreenOutdated()`——结果区显示「结果已过期」+ **产生该结果的旧条件** +
   「按当前条件重新筛选」按钮，**不渲染任何导出入口**。`wbRenderScreenJob` 与
   `wbRenderScreenTransient` 都在入口做过期判定，因此：
   - 已完成后换范围 → 旧结果立即变为过期面板（不再显示命中与导出按钮）；
   - 在途结果晚到 → 只按过期呈现，绝不冒充"本次结果"；
   - 页面刷新恢复的任务（`wbs.submitted` 为空）仍按 R1 行为正常渲染，不受影响。

**真实浏览器验证（8767，真实数据 2026-09-11）**：

反例 A（已完成 → 换范围）：

| 步骤 | 结果 |
|---|---|
| 选中 600033+600000，735 规则，真实筛选 | 「筛选完成 · 命中 1 只 | 范围 2」，导出按钮「导出本次筛选结果（1 只）」 |
| 再手动加 600519（范围变为 3 只） | 结果区 →「结果已过期 / 产生该结果的旧条件：735金叉及趋势 · 满足任意一条 · 2026-09-11 · 指定 2 只（手动输入）」；**导出按钮消失**；摘要显示新的「指定 3 只」 |

反例 B（在途结果晚到）：对真实任务 `…/result` **只延迟真实响应**（不伪造结果），
延迟期间把范围从 1 只改成 2 只，再放行响应：

| 观察点 | 结果 |
|---|---|
| 放行前 | 结果区已是「结果已过期」+ 旧条件「指定 1 只（手动输入）」 |
| 放行后 | 仍为「结果已过期」；**未出现「筛选完成」**，**无导出按钮**（`exportBtn=false`） |

### R3-02 / P2：提交锁依赖按钮 DOM，切页签后可重复提交 —— 已修

**根因**：提交时只设 `btn.disabled=true`，而 `wbRenderSummaries()` 每次重绘都按
「表单是否有效」重新赋值；没有独立的提交在途状态，入口也没有重入保护。

**整改**：新增 `wbs.submitting` / `wbe.submitting`：
- **在第一个 `await` 之前置位**，函数入口 `if (submitting) return;` 直接返回（防重入）；
- `wbRenderSummaries()` 的筛选/导出按钮 disabled 与文案都纳入 submitting
  （「提交中…」），因此摘要重绘、切页签往返都不会放开按钮；
- 提交阶段在收到任务 ID（或失败）后结束（`finally` 统一解除），之后用户可按产品
  规则主动再建任务/重试，不把整个后台生成阶段锁死；
- 筛选侧区分 `submitting`（提交在途）与 `jobRunning`（任务执行中）。

**真实浏览器验证**（攥住导出 POST 不转发，避免真的创建重复任务）：

| 观察点 | 修复前（复核实测） | 修复后 |
|---|---|---|
| 第一次点击后 | 按钮 disabled（提交中…） | 同 |
| 切「查卦象」→ 返回「批量导出」 | 按钮**重新启用** | **仍为 disabled + 提交中…** |
| 再次点击 | 发出第 **2** 个相同 POST | POST 数量始终 **1** |
| 响应返回后 | — | 按钮恢复「创建导出任务」可再次创建 |

### R3-03 / P3：筛选候选列表绕过「只接收股票」的检查 —— 已修

**整改**：`wbManualAdd` 的多候选分支在**渲染阶段**按 `wbSymType(it.type) !== "STK"`
剔除指数/ETF，并说明原因；**点击分支**再加同一道校验（防止候选项来源变化时漏判）。
导出页保持原行为（允许指数/ETF）。

**真实浏览器验证**：筛选页输入歧义代码 `000001`：

| 观察点 | 修复前 | 修复后 |
|---|---|---|
| 候选列表 | 平安银行 + 上证指数 | **只有平安银行** |
| 提示 | 只有「2 个候选请点选」 | 「000001 有 2 个候选，请在下方列表中点选；**上证指数（指数）不参与规则筛选，已从候选剔除**」 |
| 导出页输入 510300 | 可加入 | 仍可加入（沪深300ETF · 510300） |

### 文案（复核附带提到，非阻断）

导出模板说明改为「meta（口径与说明）+ 按所选标的分组生成的工作表——股票进
stock-all、ETF 进 etf-all（只选股票时不会产生空的 etf-all）」，不再让人误以为
所有文件都固定包含空 ETF 表。既有导出格式未改。
