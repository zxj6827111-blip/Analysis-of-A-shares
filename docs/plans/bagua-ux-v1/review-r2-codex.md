## 3. 必须修复的问题

### R2-01 / P1：全部 A 股筛选被当成空指定范围拒绝

位置：`service/screening.py:792`、`:807`、`:699`、`:557`。

`submit_screen_job(codes=None, scope='all')` 把 None 归一成 [] 存入任务；worker 原样传递 []；新版 run_screen 对 [] 抛出空范围错误。隔离执行实际 submit、worker、run_screen 后，任务为 error，公式引擎调用次数为 0。

同一链路还提前过滤混合范围：输入一只股票 + 一只 ETF，worker 收到的只剩股票，最终 excluded_count=0，排除提示丢失。现有集成测试把 run_screen 整体 mock 掉，没有检出这个断点。

整改：全市场在任务参数中始终保存 `codes=None`；指定范围保留原输入或显式保存有效范围和排除明细，空指定范围在提交前拒绝。不要使用真假值判断把 None 与 [] 混同。

验收：真实 submit → worker → run_screen 链路，覆盖 all/None、picked/[]、ETF-only、股票+ETF、重复代码；只替换底层行情和公式计算。全市场正常进入计算，指定空范围不进入计算，混合范围显示正确排除数。

### R2-02 / P1：前复权详情进入同卦查询时变成未复权

位置：`web/static/index_v3.html:14054`。

真实查询返回 `symbol_type='stock', adjust='tushare_qfq'`；关联操作只认 `symbol_type.toUpperCase()==='STK'`，所以把股票也当成非股票。浏览器拦截捕获的同卦请求是 `adjust='raw'`，但上方详情仍是 Tushare 前复权。

整改：统一资产类型归一化，不在不同组件分别猜测 stock/STK/index/IDX。股票关联查询沿用该结果的实际口径；摘要显示中文口径。

验收：stock/STK、index/IDX、etf/ETF 均覆盖；前复权详情 → 同卦请求仍是 tushare_qfq，结果口径一致。

### R2-03 / P1：部分年份的 ISO 周转换错一周

位置：`web/static/index_v3.html:13744`。

浏览器选择 `2021-W01`，请求提交 `20210103`，返回行情区间 **2020-12-28 至 2020-12-31**。正确 ISO 第 1 周应为 2021-01-04 至 2021-01-10。当前函数还把 2022-W01、2023-W01 分别算成 20220102、20230101，正确周日是 20220109、20230108。2026-W36 单个样本正常不足以证明算法正确。

整改：以 1 月 4 日确定 ISO 第 1 周，或由已有日历能力统一解析 ISO 年周；不要把包含 1 月 1 日的周固定当第一周。

验收：覆盖 1 月 1 日为周五/六/日的年份、跨年周、合法第 53 周与非法周；校验实际返回行情属于选择的周期，不能只断言 HTTP 200。

### R2-04 / P1：旧工作台链接打开空白内容区

位置：`web/static/index_v3.html:2826`。

`getCurrentModule()` 仍原样返回 workbench；对应 view 已移除。浏览器直达 `?module=workbench` 时仅剩全局页头。报告声称已有兼容映射，但当前代码并未实现。

整改：将 workbench 规范化到 bagua-query，再做视图切换和初始化；统一直接打开、刷新、浏览器前进后退的处理。

验收：`/` 与 `/v3` 的两个 module 值均显示唯一查询页面；普通主导航和浏览器返回不产生空白页。

### R2-05 / P2：旧新手引导仍自动弹出，指向已经删除的控件

位置：`web/static/index_v3.html:6153`、`:6223`、`:13460`。

浏览器出现旧四步引导，文字仍让用户使用右侧指数/ETF下拉、默认今天和通达信前复权；目标 bqCode/bqPeriod 等旧 DOM 已删除。遮罩实际拦截了“添加”按钮点击。

整改：移除正式页面旧初始化和自动引导触发，按原计划由用户主动开启新引导；引导指向实际存在的新控件。不影响独立旧版页面所需代码。

验收：首次访问、无 localStorage 状态时也能直接操作；如保留新引导，每一步目标存在且文字与真实界面一致，键盘可退出。

### R2-06 / P2：导出附加规则切换页签后丢失，摘要仍显示旧选择

位置：`web/static/index_v3.html:14465`、`:14481`。

浏览器：开启附加明细 → 勾一条规则 → 切到查询 → 返回导出。勾选数 1→0，附加开关仍开，摘要仍写“附加规则：20 日平台突破”，提交按钮仍可点击。提交函数虽会拒绝无规则，但界面反馈自相矛盾。

整改：导出规则用独立 Set 保存；目录刷新只移除失效 ID，重建列表后刷新摘要和按钮；不要复用筛选选择集合。

验收：跨页签、目录刷新后选择不丢；规则删除后有提示，摘要、实际提交 IDs、按钮状态一致。

### R2-07 / P1：筛选断连仍被误报为任务失效，且不恢复

位置：`web/static/index_v3.html:14326`。

只修复了导出列表的断连处理。筛选轮询 catch 仍把所有异常当成 404。隔离注入 503 后，界面生成 stale，重试定时器数量为 0。任务完成后结果端点失败，也只显示错误，不提供恢复重取。

整改：区分暂时断连、404、计算失败、结果获取失败；保留上次状态并重试；完成结果获取失败只重取结果，不能重建计算任务。

验收：运行中 503/超时后恢复、完成结果首次失败后恢复、真实 404、计算 error 四类分开验证。

### R2-08 / P1：创建同卦任务仍可清理正在运行的导出任务

位置：`api_routes/bagua.py:342`、`:391`。

同卦和导出共用 ctx.bq_export_jobs。导出创建端增加了跳过 queued/running，但 `_bq_start_same_gua_job` 的旧清理循环仍无状态保护。超过保留阈值时，从同卦入口仍可能删掉运行中导出或扫描记录。

整改：提取共用清理函数，只清理终态记录；所有写入同一容器的入口使用一致策略。

验收：在隔离容器放入超过阈值的混合任务，从导出和同卦两个入口分别创建任务，所有 queued/running 记录均保留。不要在用户实际运行任务容器上构造该测试。

### R2-09 / P2：部分成功查询的导出按钮数量与范围不一致

位置：`web/static/index_v3.html:13912`、`:13929`。

按钮文字使用成功行数量，点击后却复制所有请求代码。例如 2 只请求、1 只失败，文字“导出这 1 个标的”，下一页实际收到 2 只。

整改：按钮范围使用成功结果规范标识；若产品希望包含失败标的，必须另设明确选项并显示失败数量。

验收：全部成功、部分成功、全部失败分别核对按钮文案、来源快照和实际提交 codes。

### R2-10 / P2：筛选进入导出没有继承价格口径

位置：`web/static/index_v3.html:14449`。

从筛选结果进入导出只传递日期和股票列表，没有设置 wbEPrice；因此会沿用导出页先前口径或默认 raw。报告中的“筛选跳转口径修复”只覆盖了进入查询。

整改：从筛选进入导出默认携带 tushare_qfq，并明确显示来源和可修改状态；不能让来源快照与表单残留值混用。

验收：先把导出设为 raw，再从历史筛选进入，日期、口径、数量和规则来源全部正确；手动改变导出条件后标明与来源不同。

### R2-11 / P2：390px 下全局导航被挤成窄条

位置：`web/static/index_v3.html:94`、`:692`。

滚动回页面顶部后截图确认：三个内部页签可用，但顶部主导航几乎不可见。测量 #mainNav 宽度约 19px；根页面 scrollWidth==clientWidth，仍然存在导航不可用问题。这属于当前页面的整体适配缺陷，不断言是本次新引入。

证据：`output/playwright/bagua-r2-export-390-top.png`。另一张 fullPage 截图受当时滚动位置影响，不用它推断顶部重叠。

整改：窄屏主导航独占整行（禁用该行 flex:1 的剩余空间挤压），或提供可访问的菜单；搜索/状态信息让位于导航。

验收：390px、键盘和触摸都能打开所有主模块；不能只比较根元素 scrollWidth/clientWidth。

## 4. 建议的体验优化（不要求重做界面）

1. 标题统一为“查询卦象”，合并重复的“卦象工作台”标题；副说明直接说明用户可以做什么，减少“结果可互相跳转”等实现描述。
2. 指定股票筛选、指定标的导出支持直接输入/粘贴，复用同一标的选择组件。现在“来自查询页/手动”没有手动输入，用户仍被迫先查询一遍。
3. 同名规则显示来源、用途或版本；当前列表两条“735金叉及趋势”，仅一条多出 ⓘ，不足以帮助用户选择。不要按名字直接去重，以免合并不同规则。
4. 筛选结果显示股票名称、可搜索/分页；保留规范代码作辅助。大量结果时提供回到条件区和结果数量摘要。
5. 把 state_id、OHLC 数字和等移到可折叠的“计算依据”；操作信号、卦辞/爻辞、解读与关联操作优先呈现。
6. 中性徽章“一般”建议增加常驻短说明，区分中性与无法判断；颜色同时保留文字/图标，避免用户把缺少结论理解为明确评级。此项为展示建议，不改公式或既定红绿约定。
7. 导出模板说明与文件实际结构保持一致：既有样本是 meta、stock-all、etf-all 等工作表，避免写成“日/周/月三个工作表组”。
8. 混合查询表单摘要仍写“未复权（含指数/ETF）”，应与结果摘要一样分别说明股票和指数/ETF 口径。
9. 任务 busy 状态统一管理：筛选按钮引用 wbs.jobRunning 但当前未赋值；导出提交时修改条件/切换页签也会重新启用按钮。防重复提交、保留任务参数与展示状态应一起验证。
10. options 异步响应尚无请求序号保护，切换首个标的/口径后旧响应可能更新默认日期；筛选任务也没有与查询相同的条件版本隔离。应补乱序和切换条件反例。
