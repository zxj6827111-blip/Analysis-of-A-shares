## 一、逐项核实与整改

### R2-01 / P1：全部 A 股筛选被当成空指定范围拒绝 —— 成立，已修

**独立复现**（隔离执行真实 `submit_screen_job → _screen_run_job → run_screen`，
只替换 `resolve_screen_asof` 与 `run_weekly_review`）：

修复前：

| 场景 | 入队参数 | 结果 | 计算被调用 |
|---|---|---|---|
| 全市场 all/None | `codes=[]` | error「指定范围内没有可筛选的 A 股股票」 | 0 次 |
| 指定空 [] | `codes=[]` | error（同一条错误信息，无法区分原因） | 0 次 |
| ETF-only | `codes=[]` | error | 0 次 |
| 股票+ETF | `codes=['SSE.STK.600000']` | done | 1 次，**excluded_count=0（排除提示丢失）** |

**根因**：`submit_screen_job` 用真假值判断把 `codes=None`（全市场）归一成 `[]`，
worker 原样传入，`run_screen` 按「空指定范围」拒绝；同一处预归一还把非股票输入
提前过滤，导致 run_screen 永远算不出排除数。

**整改**（`service/screening.py`）：
- `submit_screen_job`：`scope=="all"` 时任务参数固定保存 `codes=None`（绝不写 `[]`）；
  `scope=="picked"` 时**提交前**校验为空（含全是指数/ETF）抛 `ScreenError`（400 语义），
  不建任务、不进队列；原始输入（含非股票/脏输入）原样入队。
- 新增 `_classify_codes` 把输入分成（A 股 / 指数ETF / 无法识别）三类，
  `run_screen` 据此产出排除明细：`"范围中 N 个标的为指数/ETF，不参与规则筛选；M 个输入无法识别，已排除"`。
- `codes_scoped` 改用 `codes is not None` 判断。

修复后复跑同一隔离链路：

| 场景 | 入队参数 | 结果 | 计算收到 | 排除提示 |
|---|---|---|---|---|
| 全市场 all/None | `None` | done（scope_summary=全部 A 股） | `None` | — |
| 指定空 [] | — | **提交前 400**，无任务、无入队 | 未调用 | — |
| ETF-only | — | **提交前 400** | 未调用 | — |
| 股票+ETF | `['SSE.STK.600000','SSE.ETF.510300']` | done | 1 只 | excluded=1「1 个标的为指数/ETF」 |
| 重复代码 | 3 项输入 | done | 1 只 | excluded=0（不产生虚假排除） |
| 股票+指数+脏输入 | 3 项输入 | done | 1 只 | excluded=2（1 指数 + 1 无法识别） |

前端同时保证不发空数组：真实浏览器捕获的全市场提交体为
`{"rule_ids":["tn6_735金叉及趋势"],"match_mode":"any","asof":"20260911","scope":"all"}`
（无 `codes` 字段）；指定范围为空时按钮禁用并提示原因，点击也不发请求。

### R2-02 / P1：前复权详情进入同卦查询变成未复权 —— 成立，已修

**根因**：单标的结果端点返回 `symbol_type="stock"`（小写），列表端点返回 `STK`；
关联查询只比较 `toUpperCase()==='STK'`，股票被判成非股票 → adjust 退化为 `raw`。

**整改**：新增 `wbSymType()` 统一归一（stock/STK→STK、index/IDX→IDX、etf/ETF→ETF）
+ `wbIsIdxEtf()`；详情面板、同卦/成分股入口、口径显示全部改走归一化。

**真实浏览器实测**（福建高速，2026-09-11，Tushare 前复权）：
- 拦截捕获的同卦请求体：`{"code":"SSE.STK.600033","date":"20260911","period":"DAY","adjust":"tushare_qfq"}`
  ——修复前为 `adjust:"raw"`；拦截在验证后已解除，未启动真实全市场扫描。
- 同卦面板口径显示改为中文「Tushare 前复权」（原样输出 `tushare_qfq` 字符串）。
- 混合查询表单摘要改为「股票 X / 指数·ETF 未复权」，与结果摘要口径一致。

### R2-03 / P1：部分年份 ISO 周转换错一周 —— 成立，已修

**整改**：`wbIsoWeekToSunday` 改为以 **1 月 4 日所在周为 ISO 第 1 周** 推算，
并新增 `wbIsoWeeksInYear`（53 周判定：1 月 1 日为周四，或闰年且 1 月 1 日为周三），
非法周直接拒绝；`wbRunQuery` 对非法周/月给出明确原因。

**验证（node 独立回代，2019–2026 全周覆盖）**：对每个 `Y-Wnn` 求周日，再反推该日期的
ISO 年周，要求 `(ISO年, 周) == (Y, nn)` 且为周日 —— 全量自洽。

| 输入 | 修复前 | 修复后 | 期望 |
|---|---|---|---|
| 2021-W01 | 20210103（落在 2020 年第 53 周） | **20210110** | 2021-01-10 |
| 2022-W01 | 20220102 | **20220109** | 2022-01-09 |
| 2023-W01 | 20230101 | **20230108** | 2023-01-08 |
| 2026-W36 | 20260906 | 20260906（不变） | 2026-09-06 |
| 2020-W53 | — | 20210103 | 2020 有 53 周 |
| 2021-W53 | 静默算出一个日期 | **拒绝**（2021 只有 52 周） | 非法 |

**真实浏览器实测**：选择 `2021-W01` 时实际提交 `date:"20210110"`（拦截捕获）；
非法周不发任何请求。注：浏览器 `type=week` 输入本身会清除非法周，故前端守卫属兜底。

### R2-07 / P1：筛选断连被误报任务失效且不恢复 —— 成立，已修

**整改**：
- `api()` 给 HTTP 错误附加 `err.status`、给网络错误附加 `err.network`；
- 新增 `wbScreenPollFailureKind()`：仅 404 → stale（终态，停止轮询）；其余（网络/5xx/超时）
  → transient：**保留上次状态**、显示「筛选结果获取暂时中断」+「立即重试」，4 秒后自动重试（上限 20 次）；
- 完成端点后的**结果获取失败只重取结果**，绝不重建计算任务。

**真实浏览器实测**（对真实 2 只股票的筛选任务注入 2 次 503）：
- 面板：「筛选结果获取暂时中断 / 任务本身没有失效，进度暂时读不到… / 上次状态：已排队 /
  已自动重试 1 次 / 立即重试」，错误行明示「保留上次状态并在 4 秒后自动重试」；
- 注入结束后**任务自动继续并完成**：命中 1 只（福建高速 735金叉及趋势），未被标记失效；
- 404 分支（隔离注入）：面板「任务记录已失效（服务可能已重启）」，错误行提示重新提交，
  无残留重试定时器 —— 与 503 分支行为明确区分；
- 筛选失败（计算 error）分支本就在 R1 独立判定，未回归。

### R2-11 / P2：390px 下全局导航被挤成窄条 —— 成立，已修

**根因**：`@media(max-width:980px)` 里 `.main-nav{width:100%}` 被基础规则的
`flex:1`（= `flex:1 1 0%`，flex-basis 被归零）覆盖，导航拿不到整行，只剩剩余空间。

**整改**：980 断点改 `.main-nav{flex:1 0 100%}`（显式 100% basis）+ `overflow-x:auto`；
新增 ≤640 断点：品牌区收窄、隐藏顶部快捷搜索、导航左对齐、按钮 76px。

**390×844 几何实测**（`#mainNav`）：

| 指标 | 修复前（复核实测） | 修复后 |
|---|---|---|
| 导航宽度 | ≈19px | **375px（独占整行）** |
| flex | `1 1 0%` | `1 0 100%` |
| 按钮 | 几乎不可点 | 7 个，76–96px × 48px，同一行 |
| 可达性 | — | 触摸横滑可达末尾；键盘 focus 自动滚入视口；点击末尾「数据仓库」实际切换视图成功 |
