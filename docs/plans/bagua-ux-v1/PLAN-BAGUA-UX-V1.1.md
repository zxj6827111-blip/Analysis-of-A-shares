# 卦象工作台整改计划 V1.1

**计划编号：PLAN-BAGUA-UX-V1.1**
**完整替代 V1.0，新增必读交互原型、界面呈现规范和视觉验收。执行：本地 ZCODE；复核：Codex。**

> 本文件为计划归档副本（M0）。交互原型见同目录 `bagua-workbench.source.html`（原始副本）与 `bagua-workbench-preview.html`（独立预览）。

## 一、目标、原型与实施边界

完成三个可实际使用的入口：**查卦象｜按规则筛选｜批量导出**，以及它们之间的结果跳转。

**交互原型是本计划的正式视觉附件，必须在修改前读取。**

原型的使用规则：

- 按原型实现信息层级、分组顺序、控件关系、主次按钮和操作衔接。
- 将工作台嵌入现有正式页面，保留全局导航和其他业务区域。
- 原型中的固定日期、四个示例标的、示例规则结果、模拟任务延时及设计调节工具，不进入正式业务代码。
- 原型尚未完整实现的异常、恢复和数据校验行为，以本计划为准。
- 业务正确性以本计划及真实接口为准；界面呈现以原型和下述视觉规范为准。

已确认边界：

- 三个入口本轮全部完成，不交付占位页。
- 筛选按照所选日期**当天命中**，不混用旧日期预计算结果。
- 任务支持刷新页面恢复；服务重启后的失效明确提示，本轮不建设持久化任务系统。
- 保留卦象算法、指标公式、Excel 工作表和列结构。
- 沿用现有技术栈，不引入前端框架，不改造行情仓库，不包含云服务器部署。
- 开工时记录实际 commit、工作区差异和已有失败，保护原有未提交修改。

## 二、界面呈现与交互规范

### 1. 工作台整体

从上到下排列：

**标题 → 三个任务入口 → 当前任务表单 → 条件摘要 → 主按钮 → 结果或任务记录。**

- 三个入口顺序固定为“查卦象／按规则筛选／批量导出”，首次进入默认“查卦象”。
- 桌面端入口等宽横排，分别带一句用途说明；选中项采用蓝色强调和浅色背景。
- 每个入口拥有独立表单和结果，切换时保留状态。
- 每个表单只突出一个蓝色主按钮；下载、查看详情、移除等为次级操作。
- 移除常驻长篇说明，保留字段旁短提示及可展开帮助；新手引导仅主动开启。

视觉尺寸以原型为基准：

- 内容区桌面内边距约 22px，业务分组间距约 22px，字段间距约 12–14px。
- 输入框、按钮有效高度至少 44px；控件圆角约 8px，工作台外框约 16px。
- 正文及字段文字沿用现有字体体系，辅助说明不得小于 12px。
- 默认沿用现有深色主题，颜色映射到项目已有变量，避免修改全局样式。
- 内容宽度不足 510px 时，表单和候选列表改为单列；三个入口保留，隐藏入口下方辅助说明。
- 390px 宽度下不得出现页面横向溢出、按钮文字截断或操作被遮挡。

### 2. 查卦象

按原型依次呈现：

1. **选择股票、指数或 ETF**：名称/代码输入框、添加按钮、候选项、已选标签。
2. **选择周期和时间**：日/周/月分段按钮、时间选择、数据日期提示、价格口径。
3. **查询摘要和查询按钮**。
4. **查询结果及后续操作**。

功能约定：

- 候选项展示名称、代码、交易所、资产类型；使用包含交易所及类型的规范标识。
- `000001` 等歧义输入展示候选项，不直接替用户选择。
- 批量粘贴逐项反馈识别成功、重复、歧义和无法识别，不静默丢弃。
- 搜索防抖，处理请求乱序；旧响应不能覆盖新输入。
- 日线默认最近可用交易日；周/月默认最近完整周期。日期来自后端行情覆盖和交易日历，不能用电脑日期或日历上限冒充。
- 允许指定历史日期、未完成周期；未完成及完整性未知时明确标注。
- 默认保留未复权；可选口径由后端能力决定。指数、ETF 表述为“当前系统按未复权计算”，混合查询逐项说明实际口径。

结果呈现：

- 先显示名称、周期、请求日期、实际行情区间、实际价格口径、主卦和动爻。
- 多标的采用紧凑列表，逐项展开详情；卦辞、解读、OHLC 和计算依据分层展示。
- 保留同卦、同日柱、成分股功能，入口放在相关结果旁。
- 条件改变后显示“条件已变更，请重新查询”，停用依赖旧条件的操作。
- “导出这些标的”传递查询结果的条件快照，不能读取未提交的表单。

### 3. 按规则筛选

按原型依次呈现：

1. **选择筛选规则**。
2. **选择组合方式、范围和日期**。
3. **筛选条件摘要和开始筛选按钮**。
4. **完成情况、命中股票及后续操作**。

功能约定：

- 多规则支持“满足任意一条／同时满足全部”，默认前者；未选规则不能提交。
- 规则数量多时提供检索，已选规则持续可见。
- 支持全部 A 股及指定股票；从查询页导入范围必须有明确操作。
- 本轮仅开放现有引擎能够执行的日线 XG 指标规则，不可用规则展示原因。
- 筛选采用当前正式 L1 日线及 Tushare 前复权路径，界面明示，不受查询页口径影响。
- 使用现有指标计算能力，不重写公式；临时筛选不读取或覆盖周五链共享文件作为本次结果。
- 特别检查 `persist=False` 的异常分支：数据面不可用时，不得返回已有周报缓存冒充成功。
- 显式日期没有当天可用数据时，提示可用日期，用户选择后重新执行，禁止静默回退。
- 组合运算在同一有效日期、同一股票范围内进行，按规范标识去重。
- 缺数据及规则执行失败的股票列为“未完成评估”；默认命中列表仅纳入所选规则均已完成计算的股票。

结果顶部展示范围数量、完成评估数量、缺数据数量、错误数量和命中数量。股票行展示命中规则及实际日期，提供“查卦象”和“导出本次筛选结果”。

零命中时不能导出，更不能退化为全市场导出。

### 4. 批量导出

按原型依次呈现：

1. **选择导出范围**。
2. **确认报表日期、口径和模板内容**。
3. **可选附加信号明细**。
4. **将生成的文件摘要和创建任务按钮**。
5. **导出记录**。

功能约定：

- 范围明确区分指定标的、本次筛选结果、全市场 A 股 + ETF。
- 日期、口径独立显示；从结果进入时携带来源快照，并显示“来自查询结果／筛选结果”。
- 保留现有周报模板，说明包含日柱、周卦、月卦及解读；不能让查询页“按日”暗示只导出日线。
- 保留并显示实际周/月引用日期、跨月及临时值标记。
- “另附信号规则命中明细”默认关闭；开启后必须选择规则。
- 明确提示：附加明细增加工作表，不改变主表股票范围。
- 关闭时发送 `review_rules=[]`，保留旧接口中缺省、空列表、非空列表的区别。
- 现有信号明细口径保持兼容，显示实际信号日期及回退信息，不能假定与当天筛选结果一致。

任务记录采用紧凑列表：创建时间、范围摘要、日期、状态、进度、下载或重试操作。全部导出在新页面走后台任务。

刷新后从服务端恢复；失效显示“任务记录已失效”。下载失败重试下载，计算失败使用原条件快照重试。禁止编造进度、重复提交和并发文件覆盖；记录清理不能删除执行中任务。

## 三、接口与实现约定

正式页面仍由现有 `index_v3.html` 承载，接口采用兼容性增量扩展。

| 接口 | 约定 |
|---|---|
| `GET /api/v1/bagua/instruments` | 统一名称/代码检索，返回规范标识、名称、代码、类型、交易所；复用现有目录，避免六位代码碰撞 |
| `GET /api/v1/bagua/options` | 按标的和口径返回真实可用日期、建议周期、完整性及可用价格口径 |
| `GET /api/v1/bagua/screen/rules` | 可筛选规则及不可用原因，包含可执行的隐藏指标规则 |
| `POST /api/v1/bagua/screen` | 接收 `rule_ids`、`match_mode=any/all`、`asof`、股票范围，返回任务 ID |
| `GET /api/v1/bagua/screen/jobs`、`/{job_id}`、`/{job_id}/result` | 筛选任务列表、状态和完整结果 |
| 现有 `POST /api/v1/bagua/export` | 新增默认关闭的 `force_async`；新页面调用 `async_mode=true&force_async=true` |
| 现有导出任务接口 | 补充条件摘要和实际日期，支持刷新恢复，不暴露文件系统路径 |

- 筛选采用独立内存任务容器，避免混入现有导出、同卦任务。
- 筛选使用单个后台工作线程，最多等待五个任务；队列满时返回明确的繁忙状态。
- 查询、筛选、导出各自保存条件快照，只通过明确操作传递条件。
- 日期、规则和标的在后端校验。
- 保留旧接口同步/异步行为和参数含义；Excel 列结构、核心计算值保持兼容。
- 新页面没有对应真实能力时，明确显示不可用原因，不能保留可点击但无实际作用的按钮。

## 四、执行阶段与视觉附件交付

- **M0**：冻结基线和设计附件（本目录归档）。
- **M1**：页面结构和查询（三入口框架、统一标的选择、周期日期、查询结果、状态隔离，接入真实查询接口）。
- **M2**：规则筛选（当天筛选接口、组合运算、异步任务、质量状态及查询/导出跳转）。
- **M3**：导出与恢复（独立导出表单、强制异步支持、记录恢复、下载与重试、文件唯一性及兼容性验证）。
- **M4**：生成原型与实现对照材料（查询/筛选/导出各状态 + 1440/1024/390 宽度截图）。

## 五、验收与后续复核

### 功能验收

- 名称/代码检索、歧义消解、批量输入、规范标识去重。
- 日/周/月、节假日、历史日期、未完成周期及实际数据日期。
- 请求乱序、旧结果失效、页签状态保留及条件快照传递。
- 单规则、多规则任意/全部组合，可用手工核对的小样本证明结果正确。
- 当天筛选不混入旧日期结果，不污染共享周报缓存。
- 零命中、缺数据、部分完成、计算失败分别显示。
- 三种导出范围准确，空范围不能变成全市场。
- 附加规则不改变主表范围，新旧 Excel 工作表、列结构及核心值一致。
- 刷新恢复、记录失效、下载重试、重复提交、并发文件和任务清理。
- 同卦、同日柱、成分股、规则中心及旧接口不回归。

### 视觉验收

以下任一项不满足，不能标记“界面整改完成”：

- 三入口的位置、顺序、选中态和任务用途与原型一致。
- 表单分组、标签、条件摘要、主按钮、结果区的上下顺序一致。
- 不能将大块导出设置重新放回查询表单。
- 不能用 placeholder 代替字段标签。
- 已选标的、已选规则、实际日期和口径持续可见。
- 结果中的主要结论先于长篇解释和计算细节。
- 窄屏无溢出、遮挡、截断；键盘可以完成主要操作，焦点可见。
- 正式页面没有示例数据、模拟进度或空操作按钮。
- 原型没有画出的错误状态，仍遵循相同的信息层级和视觉样式。

### 测试与交付

- 先运行相关测试，再运行 AStock 离线回归；使用隔离配置和测试输出目录。
- 更新已经过时的旧布局断言，保留有效的行为和接口保护，不能靠删除测试过关。
- 使用真实浏览器验证 `/`、`/v3`，保存截图、控制台和关键网络请求。
- 使用本地真实数据完成单股、多股、当天筛选及全市场导出，记录数据日期和规则版本。
- 提供基线、增量差异、逐项完成表、测试命令和结果、跳过原因、接口样本、Excel 样本、视觉对照及回退方法。
- 关键场景缺少真实验证时，标记“未验证”，不能声称全部完成。

**Codex 复核以本计划、归档原型、实际差异和运行证据共同为依据。** 独立检查功能、日期口径、规则组合、缓存边界、任务恢复以及视觉呈现，逐项给出通过／部分通过／不通过，最终给出本地 GO／NO-GO。云端部署另行验证。
