# A股技术指标＋卦象回测系统整体改造方案

## 一、改造目标

将当前系统从“可以运行单次回测的原型”，升级为：

> **支持12年以上历史数据、技术指标与64卦384爻自由组合、批量实验、市场阶段分析、参数对比和稳健寻优的量化研究平台。**

改造完成后，应形成以下完整闭环：

```text
建立技术条件与卦象条件
→ 配置参数测试范围
→ 批量生成实验方案
→ 自动运行回测
→ 保存全部结果
→ 按年度和市场阶段分析
→ 比较参数差异
→ 筛选候选方案
→ 样本外验证
→ 输出不同市场环境下的推荐方案
```

系统最终不是只给出一个“收益最高的参数”，而是回答：

1. 哪些条件长期有效；
2. 哪些条件只适合牛市、熊市或震荡市；
3. 哪些技术指标和卦象组合具有稳定性；
4. 哪些结果可能只是样本偶然性；
5. 不同资金和持仓方式下，实际收益和风险如何。

## 二、总体系统架构

建议将系统改造成六个业务模块：

```text
1. 策略条件中心
2. 新建回测
3. 实验中心
4. 历史任务
5. 结果对比与回测详情
6. 参数寻优与稳健性验证
```

技术结构建议为：

```text
前端展示层
├─ 条件编辑器
├─ 卦象选择器
├─ 实验配置器
├─ 历史任务
├─ 结果对比
└─ 参数分析页面

业务服务层
├─ BacktestService
├─ ExperimentService
├─ ParameterGenerator
├─ MarketRegimeService
├─ BaguaFilterService
├─ ResultAnalysisService
└─ OptimizationService

任务执行层
├─ 单次回测任务
├─ 批量实验任务
├─ 任务队列
├─ 暂停/继续/取消
└─ 失败重试

数据存储层
├─ SQLite/PostgreSQL
├─ 历史行情数据
├─ 时点股票池
├─ 卦象规则库
├─ 实验结果库
└─ Excel/CSV导出文件
```

首期继续使用 SQLite 即可，不必马上引入复杂数据库。

## 三、改造原则

### 1. 先修正结果口径，再批量测试

必须先统一：

- T日收盘产生信号；
- T+1开盘买入；
- T+2收盘卖出；
- 手续费、印花税和滑点；
- 最大回撤计算；
- 单票独立资金的净值口径；
- 完整交易数、买入数、卖出数和未平仓数。

否则批量运行几千次后，得到的结果也不具备可比性。

### 2. 所有实验必须能够复现

每次回测必须保存：

- 技术条件；
- 卦象条件；
- 所有参数；
- 回测引擎版本；
- 数据版本；
- 股票池版本；
- 卦象规则版本；
- 成本方案；
- 创建时间；
- 运行结果。

以后即使修改了指标或卦象规则，也应能够知道旧结果当时采用的规则。

### 3. 不直接暴力穷举全部组合

384个爻象任意组合数量过大。

应采用：

```text
单条件扫描
→ 有效条件筛选
→ 两两组合
→ 参数网格
→ 市场阶段验证
→ 样本外验证
```

## 四、第一阶段：修复回测口径和基础数据

这是所有后续改造的前置条件。

### 4.1 统一交易时间

整个系统统一采用：

```text
T日收盘：确认指标与卦象信号
T+1开盘：买入
T+2收盘：卖出
```

需要检查并统一：

- 正式回测；
- 事件研究；
- 页面说明；
- 交易明细；
- Excel报告；
- 历史任务参数摘要。

止盈止损单独定义，例如：

```text
盘中最高价或最低价触发
→ 按系统设定的下一可交易价格成交
```

不能与固定持有期规则混在一起。

### 4.2 修正单票独立资金模式

单票独立模式不能把几百个虚拟账户的合计权益显示成真实期末资产。

建议：

- 每只股票净值从1.0000开始；
- 按每日等权合成整体净值；
- 年化收益、最大回撤、夏普基于合成净值计算；
- 默认隐藏“虚拟账户合计权益”。

该模式主要显示：

```text
单票平均收益
单票收益中位数
参与股票数
完整交易数
胜率
盈亏比
最大回撤
标准化等权净值
```

共享资金池模式则显示：

```text
初始资金
期末资产
净利润
组合总收益
资金利用率
最大持仓数量
```

### 4.3 补齐交易指标

后端必须真正计算：

- 平均单笔收益；
- 收益中位数；
- 平均盈利；
- 平均亏损；
- 盈亏比；
- 盈利因子；
- 单笔期望收益；
- 最大单笔盈利；
- 最大单笔亏损；
- 最大连续盈利；
- 最大连续亏损；
- 平均持仓时间；
- 总手续费；
- 成本拖累。

定义必须固定：

```text
盈亏比 = 平均盈利 ÷ 平均亏损绝对值

盈利因子 = 所有盈利交易总额 ÷ 所有亏损交易总额绝对值

单笔期望收益
= 胜率 × 平均盈利
－ 亏损率 × 平均亏损绝对值
```

### 4.4 12年以上数据检查

建立数据质量报告，至少检查：

- 行情起止日期；
- 每只股票的数据覆盖率；
- 停牌记录；
- 上市和退市日期；
- ST状态；
- 除权除息；
- 涨跌停限制；
- 创业板和科创板制度变化；
- 历史印花税规则；
- 历史股票池。

必须尽量采用“时点股票池”：

> 每一个历史交易日，只使用当时已经上市且可交易的股票。

避免只使用当前股票名单造成幸存者偏差。

### 第一阶段验收

- 所有交易明细符合T+1买入、T+2收盘卖出；
- 单票模式不再展示误导性巨额期末资产；
- 核心指标都有后端真实计算；
- 不出现 `null`、`NaN`、科学计数法；
- 数据质量报告可查看；
- 原有测试全部通过。

## 五、第二阶段：回测反馈中心改造

目标是让用户看完结果后，能够立即知道下一步应调整什么参数。

### 5.1 回测详情页面

详情页设置以下页签：

```text
概览
净值与回撤
交易统计
年度/月度
市场阶段
参数分析
技术指标与卦象
交易明细
回测设置
高级信息
```

### 5.2 概览核心指标

第一屏最多展示8个指标：

```text
主收益
年化收益
最大回撤
夏普比率
完整交易数
胜率
盈亏比
单笔期望收益
```

下面增加：

- 策略净值曲线；
- 基准指数曲线；
- 回撤曲线；
- 月度收益热力图；
- 收益分布图。

### 5.3 参数回填闭环

详情页顶部增加：

```text
复制参数
修改后重跑
加入对比
加入实验
导出报告
```

“修改后重跑”流程：

```text
打开历史结果
→ 自动恢复完整参数
→ 回到新建回测页面
→ 只修改一个或几个参数
→ 保存为新任务
```

原始结果不能被覆盖。

### 5.4 结果对比

历史任务支持选择2～10个结果进行对比。

对比页面分为：

#### 参数差异

明确标记哪些参数不同，例如：

```text
持有期：1日 → 3日
止损：未启用 → 3%
卦象：关闭 → 乾为天·九五
```

#### 结果差异

统一比较：

- 总收益；
- 年化收益；
- 最大回撤；
- 夏普；
- Calmar；
- 胜率；
- 盈亏比；
- 期望收益；
- 交易次数；
- 牛熊震荡表现；
- 年度稳定性。

### 第二阶段验收

- 任意历史任务可复制参数并重新运行；
- 任意2～10个任务可比较；
- 参数差异自动高亮；
- 页面能说明收益来自哪些时间、股票和条件；
- 详情页能导出完整报告。

## 六、第三阶段：实验中心

这是实现“大量分类测试”的核心。

### 6.1 实验概念

在单次 `run_id` 之上增加：

```text
experiment_id：实验编号
variant_id：参数组合编号
run_id：具体回测任务编号
```

例如：

```text
实验：735金叉＋卦象组合测试

├─ 方案001：技术指标A，无卦象，持有1日
├─ 方案002：技术指标A，乾为天九五，持有1日
├─ 方案003：技术指标A，乾为天九五，持有3日
└─ 方案004：技术指标A＋指标B，乾为天九五，持有3日
```

### 6.2 实验配置页面

需要配置：

#### 基础信息

- 实验名称；
- 实验说明；
- 日期范围；
- 股票池；
- 回测周期；
- 资金模式；
- 初始资金。

#### 参数空间

- 技术指标；
- 指标参数；
- 指标组合逻辑；
- 卦象条件；
- 持有周期；
- 止盈；
- 止损；
- 仓位；
- 最大持仓；
- 买卖价格；
- 成本方案。

#### 测试方式

- 单条件扫描；
- 网格搜索；
- 随机搜索；
- 分层组合；
- 滚动样本外验证。

系统必须在运行前显示：

```text
预计生成参数组合：384组
预计回测任务：2,304个
预计计算量：约XX
```

参数组合过多时给出警告。

### 6.3 批量任务管理

实验任务支持：

- 排队；
- 运行；
- 暂停；
- 继续；
- 取消；
- 失败重试；
- 查看进度；
- 跳过重复参数；
- 限制并发数量。

### 6.4 实验结果页

实验完成后生成总表：

| 方案 | 技术条件 | 卦象条件 | 持有期 | 止损 | 止盈 | 年化 | 回撤 | 夏普 | 胜率 | 盈亏比 | 样本数 |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|

支持：

- 排序；
- 筛选；
- 分组；
- 收藏候选方案；
- 查看详情；
- 批量导出；
- 绘制参数敏感性图。

### 第三阶段验收

- 可以创建实验；
- 自动生成参数组合；
- 批量任务能够暂停和恢复；
- 所有结果统一保存；
- 相同参数不会重复运行；
- 可导出完整实验结果Excel。

按照此前确定的方案实施。

系统同时支持：

#### 自动分类

选择基准，例如：

- 沪深300；
- 中证全指；
- 万得全A或自建全A指数。

自动划分：

```text

熊市
震荡市
高波动
低波动
```

```text
熊市：指数位于长期均线下方，中期均线向下
```

允许创建自定义阶段：

```text
2014-07-01～2015-06-12：牛市
2015-06-15～2016-02-29：熊市
```

## 九、第六阶段：参数寻优与过拟合控制

### 9.1 分层搜索

不要直接运行所有任意组合。

#### 第一轮：基准测试

```text
技术指标，不加卦象
```

#### 第二轮：单条件测试

- 每个技术指标单独运行；
- 每个主卦单独运行；
- 每个具体爻象单独运行；
- 每个操作信号单独运行。

#### 第三轮：筛选

只保留达到最低要求的条件，例如：

- 样本数不少于300；
- 盈利因子大于1；
- 最大回撤低于上限；
- 至少一半年度盈利。

#### 第四轮：组合测试

对入选条件执行：

- 技术指标＋技术指标；
- 技术指标＋主卦；
- 技术指标＋具体爻象；
- 技术指标＋操作信号。

#### 第五轮：参数网格

测试：

- 持有期；
- 止损；
- 止盈；
- 仓位；
- 最大持仓；
- 资金模式。

### 9.2 滚动样本外验证

建议采用：

```text
训练期3年
验证期1年
每次向后滚动1年
```

例如：

```text
2014—2016训练，2017验证
2015—2017训练，2018验证
2016—2018训练，2019验证
……
```

最终重点观察：

- 参数是否在多个窗口反复入选；
- 样本外是否仍然盈利；
- 参数轻微变化后是否立即失效；
- 是否只依赖某一年行情。

### 9.3 多目标评分

不得只按总收益排名。

#### 硬性淘汰条件

- 样本数量不足；
- 最大回撤超限；
- 样本外长期亏损；
- 收益集中在极少数交易；
- 连续亏损过长；
- 参数微调后迅速失效。

#### 综合评分

建议由以下指标组成：

```text
年化收益
最大回撤
夏普比率
Calmar比率
盈利因子
单笔期望
年度盈利比例
市场阶段稳定性
样本外表现
参数稳定性
```

权重应允许配置。

最终输出：

- 全周期稳健型；
- 牛市进攻型；
- 熊市防守型；
- 震荡适配型；
- 高收益高风险型。

### 核心表

```text

experiment_variants
backtest_runs
run_parameters
run_metrics
run_year_metrics
run_month_metrics

run_bagua_metrics

data_versions
```

### 关键关系


## 十二、推荐实施顺序

不要让Grok一次性完成全部改造，建议拆成六个独立阶段，每个阶段验收后再继续。

| 阶段 | 改造内容 | 优先级 |
|---|---|---:|
| 第一阶段 | 修正交易口径、指标、数据质量 | 最高 |
| 第二阶段 | 回测反馈中心、复制参数、结果对比 | 最高 |
| 第三阶段 | SQLite、实验中心、批量运行 | 高 |
| 第四阶段 | 64卦384爻完整接入 | 高 |

## 十三、最终验收标准

系统改造完成后，至少达到：

1. 每次回测参数和结果完整保存；
2. 历史结果可以复制参数并修改重跑；
3. 可以并排比较多个结果；
4. 支持12年以上数据；
5. 使用时点股票池，降低幸存者偏差；
6. 支持64主卦和384具体爻象；
7. 支持技术指标与卦象单独、组合测试；
8. 支持批量实验；
9. 支持暂停、继续、失败重试；
10. 支持年度、月度和市场阶段分析；
11. 支持统一实验汇总表；
12. 支持参数敏感性分析；
13. 支持滚动样本外验证；
14. 最优结果不只按收益排名；
15. 能输出不同市场阶段的适用方案；
16. 相同参数和数据能够复现相同结果；
17. 所有核心计算均有自动化测试；
18. 原有单次回测功能不受影响。

## 十四、最终定位

改造后的系统应定位为：

> **A股技术指标与易经卦象多条件研究、组合回测、批量实验和稳健性验证平台。**

第一步应先实施“回测口径修正与结果反馈闭环”，再进入大规模实验和参数寻优。这样得到的结果才具有可比较性和后续研究价值。
